# Проверка и применение черновика в IDE

Локальный кандидат 1.0.10 включает native diff и создание proposed validation plan без ручного JSON. Эти действия выполняются локально, не требуют нового AI-запроса и не утверждают бизнес-корректность черновика.

## Посмотреть изменение

В preview запроса, проведения, расширения или кода формы выберите **Сравнить изменения**. Из Command Palette доступна **1С Copilot: Сравнить изменения последнего черновика**. Native diff показывает весь захваченный исходный буфер слева и точный результат одной вставки/замены справа. Несохранённые изменения входят в исходный снимок. Обе стороны — виртуальные документы; исходный файл не меняется при открытии.

При изменении или закрытии исходного контекста diff не переносится на новую версию автоматически. Нужно получить новый черновик. Применение выполняется прежней явной кнопкой, повторно проверяет source/context после await и внутри edit callback, допускается один раз и поддерживает штатный Undo. Открытый diff остаётся снимком указанной версии; он не является live approval. Полные snapshots для diff удерживаются только в памяти, не более 16 пар, с пределом 2 MiB UTF-16 на исходник. Для большего модуля остаются открыть/скопировать черновик. Crash recovery и многофайловая транзакция этим действием не реализованы.

## Создать проверку запроса

1. Подключите public profile оператора по [signed workflow](SIGNED_RUNNER_IMPORT.md).
2. В preview выберите **Проверить результат → Создать проверку запроса**.
3. Выберите полный SELECT из предложенных диапазонов. Мастер разбирает BSL string literals с кавычками и переносами `|`, не выполняет окружающий код. Конкатенации и пакеты не собираются автоматически; для них требуется переработать кандидат или другой профиль.

Если запрос использует параметры кроме `&Дата` и `&Ссылка`, оператор должен подключить public profile runner v2. После выбора SELECT мастер запросит тип и значение каждого дополнительного параметра и покажет их в финальном подтверждении. Допустимы `string`, точный `number` (до 38 цифр), `boolean`, локальная дата `YYYY-MM-DDTHH:mm:ss` и `NULL`; неизвестные, повторные, пропущенные и неиспользуемые параметры отклоняются. `&Дата` и `&Ссылка` задаются доверенной учебной фикстурой и не переопределяются. Профиль v1 откажет до подготовки задания с такими параметрами. Эти значения привязаны к подписи результата; введённый текст остаётся данными запроса, не фрагментом BSL.
4. Введите требуемый результат, ссылку/номер требования, условия тестовых данных и допущения. Описание вводится независимо от AI. Хешируется именно введённое UTF-8 описание; содержимое ссылки не загружается и не считается подтверждённым.
5. Введите ожидаемые строки вручную или загрузите UTF-8 CSV. Ожидания не подставляются из кандидата или фактических результатов.
6. Выберите ordered/multiset comparison и подтвердите summary. Пустой результат также требует явного подтверждения. Контракт всегда `proposed`, без approval/apply полномочий.
7. IDE создаст bound `prepared_query_job`. Сохраните его штатным Save As и передайте оператору. Внешний запуск и импорт receipt описаны в [SIGNED_RUNNER_IMPORT.md](SIGNED_RUNNER_IMPORT.md).

Отмена любого шага не создаёт новый host challenge. Смена исходника/pin во время диалога прекращает подготовку. Готовый JSON-план всё ещё можно импортировать отдельным действием **Импортировать готовый план проверки**. Новое задание заменяет старое только после успешного завершения мастера и native подтверждения.

## Типизированные ожидаемые строки

Колонки задаются одной строкой `Имя:тип` через `;`. Поддерживаются `string`, `number`, `boolean`, `date`, `reference`. Числа читаются как точные десятичные строки, без преобразования в JS Number; разрешены точка или десятичная запятая, экспоненциальная запись не принимается. Для дат используется локальный формат 1С `YYYY-MM-DDTHH:mm:ss` без timezone. Boolean: true/false или Истина/Ложь.

Пример **собственных** ожиданий для теста дефицита, не встроенные данные продукта:

```csv
Товар:string;Дефицит:number
A;2
```

- `NULL` и `UNDEFINED` без кавычек означают соответствующие типы. `"NULL"` в string column — буквальная строка.
- Строки с `;`, переводами строк и кавычками заключаются в двойные кавычки; внутренние кавычки удваиваются. Multiline cells доступны через CSV import; ручной ввод строки однострочный.
- Reference: `Справочник.Товары#aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee`. Empty reference: `EMPTYREF:Справочник.Товары`. Это идентификаторы вашей тестовой базы, не автоматически созданные ссылки.
- Пустая numeric/date cell не превращается в ноль или NULL. Используйте явный NULL либо корректное значение.
- Дубликаты сохраняются. Не более 64 колонок, 2000 строк и 2 MiB импортируемого файла; файл должен быть обычным локальным UTF-8 файлом.

Header без строк означает пустой ожидаемый набор и дополнительно показывается в финальном подтверждении. Это не результат отсутствующего запуска. Сравнение с proposed ожиданиями и подпись оператора имеют разные значения; ни одно не утверждает весь BSL/бизнес-процесс автоматически.
