Включены наблюдавшиеся сбои и ошибки организации проверок. Длительность отдельных инцидентов не измерялась; оценки потерянных минут не приводятся. Локальные `/tmp/` пути — вспомогательные следы, они могут исчезнуть. Постоянные отчёты указаны отдельно.

## Короткий порядок перед работой

1. Проверить Git и прочитать точку продолжения в `codex.md`. Существующий dirty worktree сохранять; сравнивать свои изменения с backup начала этапа.
2. Сначала `rg --files`/`rg -n`, затем узкий фрагмент нужного файла. Не выводить целиком большие provider, JSON manifest и несколько длинных отчётов одновременно.
3. После изменения Python: `python3 -m py_compile <изменённые файлы>`. После изменения TS-контрактов: `pnpm compile` и относящийся к изменению suite.
4. Каждый IDE-профиль получает собственный изменяемый workspace. Готовность native suite определяется `completed: true`, результатами всех checks и кодом завершения.
5. Не компилировать `out/` и не пересобирать bundles во время native source-module проверки. Сначала подготовить build/HTML, затем параллельно выполнять только независимые проверки.
6. При падении сначала определить слой: продукт, fixture, launcher, environment. Сохранить отказ и исправить причину; положительный повторный запуск не стирает первый outcome.
7. Полный regression/build/lint запускать после согласованного изменения. Повторять только затронутую проверку при исправлении harness/fixture; полный набор — если изменился общий runtime или осталось обоснованное сомнение.

## I-01. Загрузка конфигурации 1С без подходящей locale

- **Что произошло:** первая загрузка новой verification fixture в учебной Linux 1С завершилась с exit 1; кириллические XML-имена не читались в окружении процесса.
- **Причина потери времени:** locale не проверили до дорогой загрузки конфигурации.
- **Исправление:** для процессов 1С заданы `LANG=ru_RU.UTF-8`, `LC_ALL=ru_RU.UTF-8`; последующие load/update, CheckConfig и Enterprise завершились успешно.
- **Предотвращение:** проверять наличие locale и её фактическое значение в выбранном runner-профиле до загрузки. Этапы create/load/check/run запускать раздельно и читать их логи.
- **Evidence:** [foundation report](../tests/VERIFICATION_FOUNDATION_REPORT_2026-10-29.md), [первый отказ](../tests/evidence/verification-foundation-2026-10-29/engine-first-attempt.json).

## I-07. UTF-8 hash не различал отдельные JS code units

- **Что произошло:** при разработке snapshot обнаружено, что UTF-8 encoding заменяет непарный surrogate на replacement character; разные исходные JS-строки могли получить одинаковое представление до SHA-256.
- **Причина дополнительной работы:** требовалось уточнить контракт текстовой идентичности, обновить новые DTO, тесты и native assertions.
- **Исправление:** snapshot/prompt/candidate/change text hashes используют UTF-16LE с явным `textHashEncoding`; DTO hashes остаются canonical JSON UTF-8, file hashes — по байтам файла.
- **Предотвращение:** выбирать кодировку вместе с единицами offsets до внедрения hash-контракта. Проверять CRLF, non-BMP и unpaired surrogates. Не смешивать text hash, JSON hash и file hash.
- **Evidence:** [EditorSnapshot API](EDITOR_SNAPSHOT.md), `tests/editor_snapshot_test.js`.

## I-08. TypeScript narrowing не учёл побочный эффект guard

- **Что произошло:** первая компиляция `QueryComparisonJob` дала TS2367: повторное сравнение `state === 'cancelled'` считалось недостижимым после предыдущего guard, хотя вызываемый host callback потенциально меняет состояние.
- **Причина потери времени:** изменение состояния через вызов не соответствовало control-flow narrowing компилятора.
- **Исправление:** проверка отмены выделена в `assertNotCancelled()` и выполняется до и после host guard. Компиляция и 13 предметных групп прошли.
- **Предотвращение:** проверки terminal states вокруг внешнего callback выражать отдельными методами и тестировать повторный вход/побочные эффекты. Не маскировать проблему приведением типа.
- **Место:** `src/features/compare-query-results/model/queryComparisonJob.ts`, стадия provided-data comparison.

## I-09. Слишком большие выводы инструментов обрезались

- **Что произошло:** несколько пакетных чтений полных файлов/отчётов превысили общий output budget. Часть нужной информации пришлось читать повторно; передача контекста потребовала восстановления отдельных результатов из JSON evidence.
- **Причина потери времени:** независимые вызовы были объединены, но суммарный объём не был ограничен по содержимому.
- **Исправление:** чтение конкретных строк/полей JSON, отдельных failures и коротких summaries.
- **Предотвращение:** для каждого чтения формулировать вопрос. Использовать `rg -n`, ограниченный `sed`, Python extraction нужных ключей. Полный лог писать в файл, в tool output выводить только итог и ошибки. Проверять суммарный бюджет параллельных результатов.
- **Место:** этапы EditorSnapshot и provided-data comparison; фактическая потеря времени отдельно не измерялась.

## I-10. Dockerfile принял image ID за registry reference

- **Что произошло:** `FROM sha256:<image-id>` был интерпретирован как имя repository/tag; BuildKit попытался получить `docker.io/library/sha256` и завершился отказом.
- **Причина потери времени:** формат local image ID был ошибочно использован как Dockerfile image reference.
- **Исправление:** trusted fixture готовится в собственном контейнере через `docker create` из точного local image ID, затем фиксируется новый digest. Runtime использует `--pull=never`; автоматическая загрузка image при запуске задания запрещена.
- **Предотвращение:** отдельно проверять поддерживаемый формат reference выбранного Docker API; сохранять исходный image ID и итоговый digest. Проверить простую операцию до длинной подготовки платформы.
- **Evidence:** лабораторная попытка `/tmp/1c-query-runner-image-20261029-first/build.log`; сводка сохраняется в отчёте query runner.

## I-11. Permissions и пути логов при запуске 1С без capabilities

- **Что произошло:** сначала `worker.py` не читался из-за mode/ownership скопированных файлов. После исправления чтения root с `cap-drop=ALL` не мог создать `/runner/base` в каталоге другого владельца. Часть ранних запусков ждала до timeout. После переноса рабочего каталога некоторые `/Out` пути ещё указывали на старый `/work`; код выхода 0 не сопровождался нужным логом.
- **Причина потери времени:** ошибочное ожидание, что root без `DAC_OVERRIDE` обходит обычные файловые права; разрозненные абсолютные пути; ранние диагностические файлы исчезали вместе с контейнером.
- **Исправление:** rX permissions только для собственных fixture copies; подготовка от владельца каталога; все prepare-логи через `WORK`; проверки наличия новой базы/логов. До удаления неуспешного prepare-контейнера сохраняются известные логи и screenshot при наличии.
- **Предотвращение:** до платформы проверить uid/gid, доступность binary/config, возможность записи базы и `/Out`. Cleanup должен сохранять bounded diagnostics до удаления собственной среды. Runtime-профиль не ослаблять для исправления подготовительных permissions.
- **Evidence:** `create.log` с `Permission denied` в `/tmp/1c-query-runner-image-20261029-visible/failure-logs/`; итоговый runner report.

## I-12. Query Null оказался недопустимым значением стандартного JSON serializer 1С

- **Что произошло:** новый engine adapter вычислил правильную строку `A / 2`, но `ЗаписатьJSON` остановился на `reason = Null`. Клиент показывал общую ошибку, result JSON оставался неполным, первый runtime получал `failed` после timeout. Добавление POSIX account для UID 10001 не устранило эту ошибку.
- **Причина потери времени:** смешаны тип query Null и значение, используемое JSON serializer; исключение в startup handler сначала не попадало в машинный результат.
- **Исправление:** для JSON null используется `Неопределено`; query Null в typed cell остаётся `{type: "null"}`. Внешний startup catch сохраняет причину; worker проверяет client error и валидность JSON. Ошибки протокола не повышаются до успешного исполнения.
- **Предотвращение:** проверять весь native serialization path. В реальном engine corpus теперь отдельный typed-NULL сценарий. Сохранять failure artifact до cleanup; после исправления повторять положительный и отрицательные controls.
- **Evidence:** `/tmp/1c-query-runner-serialization-error.json` содержит частичный результат и точную ошибку `ЗаписатьJSON`; конечный корпус — correct / controlled-defect / schema-error / typed-null.

Повтор I-09 на этапе runner: несколько начальных чтений снова превысили общий output budget. Для следующих этапов нужно ограничивать суммарный вывод всего `functions.exec`, а не только каждого вложенного shell вызова; minified XML разбирать через parser вместо `head`.

## I-14. Ошибка завершения Xvfb скрыла outcome 1С

- **Симптом:** actual `run-prepared` завершился отказом Docker из-за `process.wait(timeout=5)` после SIGTERM Xvfb. Первичная диагностика движка затерялась за исключением `finally`; первый native прогон с engine не дошёл до импорта.
- **Причина:** trusted test worker рассчитывал на гарантированное завершение вспомогательного Xvfb по SIGTERM. Изоляция сохранилась: controller удалил собственный контейнер, успешный receipt не был принят.
- **Исправление:** bounded terminate → kill → wait, сохранение ограниченных stage logs в failed observation. Создан новый image только с изменением worker, исходный base/config сохранены; проверен исходный fixture hash, пересчитан новый worker/fixture hash. Старый image/evidence не заменены.
- **Предварительная проверка:** cleanup subprocess не должен скрывать первичную ошибку. На обновлённом image выполнить положительный/отрицательные engine controls; нельзя ослаблять resource/network/read-only policy ради PASS.
- **Evidence:** attempts b/d/e в `tests/evidence/signed-runner-import-2026-10-30`; `tests/runner_fixture/update_worker_image.py`.

## I-15. Native API позволяет редактировать виртуальный отчёт

- **Симптом:** `TextEditor.edit` вернул true для URI `TextDocumentContentProvider`, хотя обычный ввод запрещён. Предположение теста о безусловном отказе API было неверным.
- **Причина:** read-only редактор для пользователя не является запретом WorkspaceEdit со стороны extension host. Игнорирование собственных document-change events оставляло случайные programmatic edits до следующего refresh.
- **Исправление:** provider восстанавливает текст из проверенного evidence при расхождении; canonical update не запускает цикл. Native suite отдельно проверяет отказ обычного `type` и восстановление после API edit, не маскирует последний как rejected edit.
- **Граница:** это защита достоверности отображения от случайного изменения, не sandbox против вредоносного расширения с доступом к host.
- **Evidence:** attempt d (7/8) и final e (8/8 в каждом IDE), host regression restoration/no-loop.

## I-16. Native suite запущен до завершения подготовки профиля

- **Симптом:** attempt c запущен пока отдельная tool session ещё выполняла image commit; профиль ещё не был записан, остался неполный native result.
- **Причина:** последовательная зависимость ошибочно считалась завершённой после получения session ID.
- **Исправление:** дождались окончания build tool, проверили профиль и запустили новый output. Неполный launcher остановлен; старые результаты сохранены как failure evidence. Добавлен ранний file preflight в launcher.
- **Предотвращение:** зависимые вызовы запускаются только после exit 0 и проверки ожидаемых outputs. `session_id` означает работающий процесс, не готовый результат.

Повтор I-09 при восстановлении контекста signed import: даже короткие пакетные чтения несколько раз превысили запрошенный output budget. Для следующего продолжения использовать итоги из report/manifest, читать только failures и не занижать budget ниже заранее ограниченного содержимого.

## I-17. Побочный эффект внутри native test locator

- **Симптом:** первый extension-ux native прогон не завершил мастер; `wizardChoices.shift()` вызывался внутри predicate `find` и потреблял несколько действий за один диалог. Последующие проверки не получили prepared job.
- **Исправление:** выбор очередного действия выполнен один раз до поиска. Ожидаемый wizard flow сохранён; production UI и проверки контракта не ослаблялись. Final native: 9/9 в каждой IDE.
- **Предотвращение:** predicates не изменяют очередь сценария. Сохранять первоначальный refusal; последующие ошибки отсутствующего артефакта считать зависимыми, не самостоятельными багами продукта.

## I-18. Проверки опирались на неверное представление существующего контракта

- **Симптомы:** рефакторинг bounded JSON reader изменил прежний текст отказа non-regular JSON file и сломал regression. Packaged smoke попытался записать несуществующую настройку `normahub1c.uiLanguage`; язык панели фактически хранится в extension preferences.
- **Исправление:** JSON wrapper сохраняет прежний отказ, общий text reader используется для CSV. Packaged smoke проверяет реальные RU/EN catalogues и language registrations; переключение самой панели остаётся host/browser evidence, не объявляется native setting smoke.
- **Предотвращение:** перед обобщением helper сохранять вызываемые контракты; перед тестом settings сверяться с contributes и настоящим хранилищем, не создавать дублирующую настройку ради PASS.

## I-19. Line-oriented tokenizer не давал полный multiline literal

- **Симптом:** первый query-choice unit test вернул 0 вариантов для корректного CRLF/pipe BSL literal. Существующий lexer выдаёт части по строкам, что не является полным диапазоном строковой константы для runner.
- **Исправление:** отдельный небольшой scanner полного literal с UTF-16 offsets, comment/escaped-quote/CRLF handling и отказом concatenation. Общий inline tokenizer не менялся без отдельной приёмки. Query-choice tests и native real-engine wizard прошли.
- **Предотвращение:** проверять реальные token boundaries перед использованием lexer как complete-expression parser. Сканирование не утверждает синтаксис всего BSL-модуля.

## I-20. Live 1017 расходует output budget на reasoning

- **Симптом:** первые 3 product calls вернули HTTP 200/length с 3000 completion tokens почти полностью в reasoning. HTTP-only старый benchmark назвал бы это успешной связью, но продукт правильно отказал.
- **Действие:** прогон остановлен без automatic paid retries. Frozen corpus сохранён. Exact requested ID подтверждён каталогом; response ID остался базовым alias, без искусственного переименования.
- **Диагностика:** thinking disabled не помог в одном control; low effort дал ответ в другом, но source low profile всё ещё имеет truncation. Это partial mitigation, не законченная совместимость. Нужна backend route/control проверка по request IDs.
- **Предотвращение:** разделять доступность, finish reason, model identity, emitted item, executed result и пользу. Не повышать общий лимит и не менять модель без измерения нового профиля.
- **Evidence:** LIVE_NORMAHUB_1017_REPORT_2026-10-31.md, raw runs a/b и controls.

## I-21. Native harness без product configuration и ненадёжный UI replay

- **Симптом:** companion-only IDE не зарегистрировал normahub1c settings; 3 inline attempts завершились до HTTP. После primary VSIX install появились настоящие completions, но native commit/no-change и mixed Tab replay не дали устойчивого подтверждения acceptance; были unexpected edits.
- **Исправление стенда:** primary VSIX установлен только в собственный новый profile, без API key в SecretStorage; model transport source test остаётся отдельно обозначен. Offline replay не делает новых платных calls, сравнивает точный expected text вместо любого изменения буфера.
- **Предотвращение:** проверять language/config registration до inference. GUI/physical Tab выполнять на выделенном display с изолированным вводом; не трактовать чужой/другой edit как acceptance и не повторять focus/Tab на рабочем desktop ради зелёного итога. Native acceptance оставлен unverified.

## I-22. Нормализатор отбрасывал корректный строковый argument

- **Симптом:** реальный ответ `"Привет!"` после `Сообщить(` отфильтрован как не BSL, потому что нет semicolon/call/keyword.
- **Исправление:** узкое разрешение полного quoted literal в уже открытой argument position; standalone prose, comment context и malformed string по-прежнему отвергаются. Полная регрессия и offline replay реального ответа прошли; нового live/Tab PASS после fix не заявляется.

## I-23. stdin и объём model catalogue при live preflight

- **Симптом:** обычный exec pipe закрыл stdin до ввода; credentials не передавались, API call не был сделан. Первый вывод model catalogue также превысил budget из-за поиска слова DeepSeek во всех описаниях чужих cards.
- **Исправление:** private non-echo TTY только для ввода в память, затем single-use mode-0600 Unix broker; нет key в env/argv/files. Сначала дождаться Waiting prompt. Catalogue выводить/сохранять по точному `id`, не regex по полным descriptions.
- **Предотвращение:** отсутствие runtime session ID не означает, что stdin ждёт. Для secrets не включать echo и не записывать shell commands с ключом. Не копировать весь IDE profile или catalogue разрешённых ключу моделей в публичный evidence.

## I-24. Docker commit учебной конфигурации превысил короткий таймаут

- **Симптом:** Designer загрузил и проверил новую конфигурацию, но первый `docker commit` не завершился за 120 секунд; профиль v2 не был создан. Это не было ошибкой платформы или истечением учебной версии.
- **Исправление:** образ получил уникальную временную метку и идентификатор сборки, таймаут commit увеличен до 600 секунд; профиль записывается только после проверки точного immutable image ID. Повторная сборка завершилась и прошла real-engine controls.
- **Предотвращение:** не принимать успешный `LoadConfig` за готовый образ, не выбирать Docker image по дате и не запускать повторный commit без отдельной идентичности сборки.

## I-25. Native test ожидал поле, которого нет в wire request

- **Симптом:** первый IDE parameter workflow прошёл мастер, но тест сравнил `job.request.query` с SELECT. В wire request SELECT представлен исходным кодом и диапазоном; `query` выводится только после парсинга. Следующие проверки упали из-за отсутствующего файла задания.
- **Исправление:** тест извлекает полный SELECT из `candidateCode` и точного `selection`, затем проверяет prepared job и внешний запуск; 6/6 в VS Code и Cursor.
- **Предотвращение:** перед утверждением тестового оракула сверять фактическую wire schema, а зависимые ошибки после первой не считать отдельными дефектами продукта.

## I-26. Подмена отчёта проверялась после устаревания исходника

- **Симптом:** после изменения BSL меню корректно открывало исторический отчёт, и тест не достигал импорта подменённого receipt.
- **Исправление:** проверка подписи выполняется при актуальном исходнике; изменение файла и invalidation проверяются последним шагом. Native test подтвердил отказ подмены до stale-состояния.
- **Предотвращение:** негативный сценарий должен достигать конкретной границы доверия; фиксировать последовательность source-current → tamper → stale.

## I-27. CSS-селектор и пробелы мешали физическому Tab-тесту

- **Симптом:** серый текст подсказки реально отображался в VS Code, но тест искал старый `.ghost-text`; Monaco показывал другой класс и неразрывные пробелы. Первые прогоны не нажимали Tab и честно зафиксировали отказ проверки.
- **Исправление:** драйвер проверяет фактически отрисованный текст активного Monaco-редактора, нормализуя только U+00A0 для сопоставления. Tab/Escape отправляется только после подтверждения видимой подсказки. Финально в обеих IDE 4 точных вставки и 1 отклонение.
- **Предотвращение:** проверять снимок и DOM при неуспехе visual gate; не вызывать programmatic commit как замену физическому Tab.

## I-28. CLI сохраняет отказ до запуска движка

- **Симптом:** первый real-engine negative test ожидал отсутствия output directory, хотя operator CLI создаёт её заранее и записывает `failure.json` при preflight refusal.
- **Исправление:** проверка утверждает наличие refusal record и отсутствие challenge/receipt/контейнера; все три вида неверных параметров отвергнуты без запуска движка.
- **Предотвращение:** различать служебную директорию отказа и фактическое выполнение задания.

## I-29. Packaged smoke был привязан к номеру прошлого VSIX

- **Симптом:** первая установка 1.0.10 в изолированный VS Code прошла, но packaged smoke ожидал literal `1.0.9`; из-за раннего assertion он не активировал расширение, и следующий тест handlers зависимо провалился.
- **Исправление:** launcher читает версию непосредственно из проверяемого VSIX и передаёт тесту вместе с hash bundle. Повторный installed smoke прошёл 4/4 в VS Code и Cursor; release QA сверил bytes пакета с исходным worktree.
- **Предотвращение:** тест артефакта должен проверять выбранный immutable пакет, а не номер предыдущего кандидата в исходнике теста.

## I-30. Source-provider Tab evidence не покрывало сам установленный VSIX

- **Исправление:** добавлен isolated packaged test: SHA bundle из точного VSIX сверяется с установленным расширением, HTTPS подменяется только в extension host синтетическим ответом из сохранённого live корпуса; без импорта source provider. В VS Code/Cursor пакет прошёл четыре физических Tab и один Escape.
- **Предотвращение:** при утверждении пользовательского поведения различать source-module suite, installed-package suite и live gateway suite; каждый уровень фиксировать отдельно.

## I-31. После Tab уходил лишний автоматический запрос

- **Симптом:** VSIX 1.0.10 при штатном debounce 250 мс делал второй controlled HTTPS-вызов после каждого из четырёх принятых ghost-дополнений в обеих IDE, хотя пользователь ещё не печатал новый текст. Тестовый debounce 0 мс показал то же. Реальное списание токенов тест не измерял.

Новый ввод и manual invoke разрешены. Unit lifecycle и установленный VSIX 1.0.11 подтвердили 1 вызов до Tab, 0 дополнительных после Tab/Escape при 250 мс в обеих IDE.
- **Предотвращение:** в платном inline-сценарии измерять вызовы до и после принятия подсказки отдельно; не считать точную вставку достаточной проверкой стоимости.

## I-34. Live harness не открыл Unix-сокет из-за длины пути

## Как дополнять
