## Следующая точная последовательность

1. Владелец перевыпускает раскрытые ранее NormaHub/Open VSX ключи. Новый NormaHub key кладёт **без отправки в чат** в `.private/normahub-live-key` (mode 0600), сообщает бюджет до 30 вызовов. Агент запускает canary, затем оставшийся frozen corpus и анализирует долю полезных результатов, p95 и стоимость. Отдельный установленный VSIX должен выполнить хотя бы один настоящий AI-запрос без source-module подмены.
2. Владелец входит в GitHub Release draft `v1.0.12`, скачивает VSIX и `SHA256SUMS` или предоставляет агенту подключённый GitHub доступ. Проверить hash, запустить installed smoke на этих байтах. Если CI artifact имеет иной hash, это ожидаемо до сравнения payload: не подменять его локальным файлом.
3. Владелец создаёт Marketplace Trusted Publishing policy: owner `normahubcc`, repo `1c-bsl-ai-copilot`, workflow `release.yml`, environment пустой; сохраняет **ротированный** `OVSX_PAT` в GitHub Secrets. После завершения gate 4 и проверки draft запускает `gh workflow run release.yml --ref v1.0.12 -f promote=true` через авторизованный GitHub CLI/API. Следить за двумя upload steps и открытием prerelease. Публикация в двух реестрах не атомарна: если первый upload прошёл, а второй нет, остановить анонс, сверить реальные версии и восстановить только недостающую площадку; слепой повтор может получить ошибку дубликата.
4. После появления 1.0.12 в обоих каталогах скачать пакеты, сверить версию/состав и выполнить установку в чистые VS Code/Cursor. Лишь затем подставить ссылки и фактические кадры в тексты, провести ревью разработчиком 1С и отправить анонс/Инфостарт/Habr по очереди. Product Hunt и MCP directories — отдельные запуски после собственных gates.

Не делать вывод «100% production» по успешному CI: B2B/Team GA требует самостоятельных доказательств для tenant isolation, прав, SLA, стоимости, ERP и Windows-контуров.
