# Размещение 1C BSL AI Copilot

> Актуальный release gate и двухэтапный CI-процесс на 2026-11-10: [RELEASE_AND_GROWTH_2026-11-10.md](RELEASE_AND_GROWTH_2026-11-10.md). Пример для 1.0.8 ниже исторический и **не является командой для текущего кандидата 1.0.11**. Тег теперь создаёт GitHub draft; публикация в Marketplace/Open VSX запускается вручную на том же теге после проверки пакета. Перед публикацией на Инфостарте проверьте [действующие правила](https://infostart.ru/about/rules/publishing_rules/): ограничения на коммерческие предложения, внешние контакты и ссылки могут влиять на формат материала.

Порядок: проверенный исходник и VSIX → GitHub Release → Marketplace/Open VSX → профильные карточки → отдельная поставка MCP. Эта инструкция не означает, что кандидат уже опубликован или прошёл все production-проверки.

## GitHub

1. Войдите через `gh auth login` и выберите аккаунт с правами записи в `normahubcc/1c-bsl-ai-copilot`.
2. Просмотрите точный diff кандидата. Сейчас изменения незакоммичены; нельзя привязывать новый бинарник к старому коммиту, выдавая его за исходник сборки.
3. После согласования состава изменений создайте коммит, выполните проверки, соберите VSIX из этого SHA и отправьте коммит и тег версии в репозиторий.
4. Откройте **Releases → Draft a new release**, выберите существующий тег, приложите VSIX, SHA-256 и описание изменений. Сохраните черновик и проверьте ссылки перед публикацией.

Для текущего имени версии, после подготовки правильного удалённого тега:

```bash
gh release create v1.0.8 \
  /home/user/Desktop/normahub/normahub-github/repos/1c-bsl-ai-copilot/1c-bsl-ai-copilot-1.0.8.vsix \
  --repo normahubcc/1c-bsl-ai-copilot \
  --verify-tag --draft \
  --title '1C BSL AI Copilot 1.0.8' \
  --notes-file docs/releases/1.0.8.md
```

`--verify-tag` предотвращает автоматическое создание тега от постороннего состояния основной ветки. Статус pre-release выбирается по результатам проверки кандидата. [Руководство GitHub](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository?tool=cli), [GitHub CLI](https://cli.github.com/manual/gh_release_create).

## Open VSX и Visual Studio Marketplace

Существующие карточки:

- [Open VSX](https://open-vsx.org/extension/normahub/1c-bsl-ai-copilot).
- [Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=Normahub.1c-bsl-ai-copilot).

В обе площадки передаётся один проверенный VSIX с одинаковым `publisher.extension`. Токен Open VSX не даёт доступа к Microsoft Marketplace, GitHub или другим площадкам. Секреты не должны попадать в командную историю, описания релизов, исходники и логи. Для автоматизации используйте секретное окружение либо хранилище CI.

После публикации отдельно проверьте версию в API каталога, скачанный пакет и установку через поиск редактора. Cursor использует Open VSX через собственный прокси с проверкой пакетов, поэтому публикация в Open VSX не доказывает немедленное появление в поиске Cursor. [Документация Cursor](https://prod.cursor.com/help/customization/extensions).

## Инфостарт

1. В профиле выберите **Создать → Создать публикацию** и сохраните черновик.
2. Оформите карточку инструмента: практическая задача, поддерживаемые редакторы, установка, два-три воспроизводимых сценария, ограничения и способы получения поддержки.
3. Укажите, что само расширение распространяется по MIT, а облачные AI-запросы требуют аккаунта NormaHub и оплачиваются отдельно. Локальные возможности отделите от AI-зависимых.
4. Добавьте VSIX в область файла программы, а скриншоты — в раздел изображений. Укажите исходный код и проверьте допустимый способ его предоставления по выбранному типу публикации.
5. Выберите подходящий вид объекта и категории, проверьте черновик, затем отправьте его на модерацию.

Условия облачного сервиса необходимо описывать прямо: бесплатный файл с обязательной оплатой внешнего AI нельзя представлять как полностью бесплатный продукт. Категорию и допустимость размещения определяет Инфостарт; автоматическая отправка не гарантирует одобрения. [Оформление публикации](https://infostart.ru/about/help/28158/683216/), [правила площадки](https://infostart.ru/about/rules/publishing_rules/).

## Официальный MCP Registry

Реестр публикует описание устанавливаемого MCP-сервера. VSIX не является самостоятельным npm-пакетом MCP. Для этого канала нужно сначала подготовить и проверить отдельную поставку сервера, например npm-пакет с `bin/mcp-server-1c.js` и `dist/mcp-server.js`.

1. Выберите принадлежащее вам имя пакета и пространство имён реестра, например `io.github.normahubcc/1c-copilot`, если владение этим GitHub namespace подтверждается вашим аккаунтом.
2. Подготовьте npm-пакет с bin entrypoint, лицензией, инструкцией запуска и метаданными подтверждения владения. Проверьте установку из упакованного архива в пустой каталог без зависимостей проекта расширения, затем опубликуйте пакет.
3. Создайте `server.json` актуальной схемы: имя, версия, репозиторий, описание и `packages` со способом запуска `stdio` и реально опубликованным npm-пакетом той же версии.
4. Установите официальный `mcp-publisher`, выполните `mcp-publisher login github`, затем `mcp-publisher validate` и публикацию по текущей инструкции CLI. Для доменного namespace потребуется подтверждение домена вместо GitHub namespace.
5. Проверьте карточку через Registry API и подключение в настоящем MCP-клиенте.

Текущие локальные MCP-инструменты не вызывают AI и не требуют NormaHub API key. Не объявляйте такой ключ обязательным для этой поставки. Авторизация публикации MCP Registry и авторизация npm — разные доступы. [Официальные требования](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/server-json/official-registry-requirements.md), [формат server.json](https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/server-json/generic-server-json.md).

## Glama MCP Directory

Откройте [каталог серверов](https://glama.ai/mcp/servers), выберите **Add MCP Server**, укажите GitHub-репозиторий, название и краткое описание именно MCP-компонента. Репозиторий должен объяснять самостоятельную установку и запуск сервера. После индексации проверьте найденные инструменты, лицензию и результаты проверок Glama. При необходимости добавьте `glama.json` по актуальной схеме площадки.

Регистрация карточки open-source сервера и владение удалённым connector — разные сценарии. Для существующего локального stdio-сервера не нужно выдумывать удалённый HTTPS endpoint. [Инструкция Glama](https://glama.ai/mcp/faq).

## Product Hunt

Из личного аккаунта откройте **Submit → New Product**. Подготовьте название, короткий англоязычный tagline, ссылку на продукт, описание, логотип, галерею, короткое реальное демо и комментарий автора. Объясните целевую аудиторию: разработчики 1C:Enterprise, работающие с BSL в редакторе. Укажите RU/EN, реальные возможности, цену облачных запросов и ссылки установки. Просмотрите черновик, выберите дату запуска и обеспечьте ответы пользователям в день публикации. [Руководство запуска](https://help.producthunt.com/en/articles/17350772-launch-guide).

## Что можно автоматизировать с доступом

GitHub Release, публикацию в Open VSX/Marketplace, выпуск npm-пакета и регистрацию MCP можно выполнять через CLI/API с необходимыми правами. Инфостарт, Glama и Product Hunt потребуют доступного авторизованного интерфейса или подходящего API. Подготовить материалы и заполнить доступные формы можно автоматически; вход, 2FA, подтверждение владения и решения модераторов нельзя обещать автоматизировать.

Передавать пароли и резервные коды не нужно. Предпочтительны штатный вход, отдельные ограниченные токены и секреты CI. Предоставление доступа само по себе не заменяет выбор конкретной версии и площадок для публикации.
