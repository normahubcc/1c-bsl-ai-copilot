# Внешняя обработка: исходники для ручной сборки

Это экспериментальный адаптер к Sidecar. В пакете находятся модуль объекта и модуль формы; готовый бинарный `.epf` и подтверждённая матрица конфигураций отсутствуют.

## Сборка в Конфигураторе

1. Создайте внешнюю обработку с управляемой формой. Перенесите `NormaHubCopilot_Module.bsl` в модуль объекта, `NormaHubCopilot_Form.bsl` — в модуль формы.
2. Создайте строковые реквизиты объекта: `ХостSidecar`, `ТокенSidecar`, `ПутьКФайлуМетаданных`, `ИмяДокумента`, `ТабличнаяЧасть`, `ИмяРегистра`, `ПоляЗапроса`, `ИсходныйКодBSL`, `РезультатПроверкиИТС`, `СгенерированныйКод`, `ЛогТЖ`, `РезультатАнализаТЖ`. Создайте числовой `ПортSidecar`. Имена дополнительных реквизитов сверяйте с модулем формы. Для поля токена включите скрытие ввода; токен не включайте в поставляемую обработку.
3. Добавьте команды формы и свяжите их с обработчиками `КомандаВыгрузитьМетаданные`, `КомандаПроверитьКод`, `КомандаСгенерироватьЗапрос`, `КомандаСгенерироватьBDD`, `КомандаАнализТЖ`.
4. Проверьте синтаксис модулей в своей версии платформы, сохраните `.epf`, запустите в тестовой базе.

## Подключение

Запустите `python3 sidecar/main.py daemon` на машине, с которой выполняются серверные HTTP-вызовы обработки. Нужны Python 3, Node.js и `dist/toolbox-cli.js` (в VSIX уже включён). Loopback `127.0.0.1` в клиент-серверной базе относится к серверу 1С. Обработка использует обычный HTTP, как локальный Sidecar.

Если задан `SIDECAR_AUTH_TOKEN`, заполните `ТокенSidecar` тем же значением. Оно передаётся только в заголовке Authorization. Не публикуйте токен и не добавляйте его в исходники. Ключ NormaHub для AI задаётся отдельно в окружении Sidecar.

## Контракты

- Запрос контроля дефицита: заполните документ, табличную часть, регистр и `ПоляЗапроса`. Поля перечисляются через запятую: все измерения, затем один числовой ресурс; должны существовать в обеих таблицах. Генерируется запрос для последующей интеграции, без движений и блокировок документа.
- BDD: локальный каркас с заданными объектами. Шаги Vanessa и реальные тестовые данные добавляются разработчиком.
- Аудит и ТЖ: локальные эвристики общего ядра расширения. Отсутствие совпадений не означает полную проверку.
- Метаданные: укажите абсолютный путь к файлу **на сервере 1С** в реквизите `ПутьКФайлуМетаданных`. JSON записывается серверным модулем. Скопируйте полученный `metadata.json` в корень проекта VS Code и нажмите «Сканировать». Расширение валидирует импорт; ошибки показываются пользователю.

Нужны live-проверки на вашей платформе и конфигурации: синтаксис, доступность серверного HTTP, файловые права и обработчики формы. Автоматические тесты Python/TypeScript не выполняют эти BSL-модули.
