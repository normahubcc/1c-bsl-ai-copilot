# Проверка поведения 1С

Прочитай проектные AGENTS.md и codex.md. Для будущих counterexample/diff/rules workflows используй `docs/AI_BUSINESS_VERIFICATION_SPEC.md`; они не считаются уже реализованными.

## Контракт до кандидата

Из требования и реальной схемы зафиксируй ожидаемые значения/типы, ключи сравнения, параметры времени, условия доступа и допустимые изменения. Не подгоняй oracle под ответ AI или старый код. Для неоднозначного правила запиши конкретный вопрос; предлагаемая интерпретация остаётся гипотезой до утверждения.

Подбирай только применимые граничные случаи: NULL и отсутствие остатка; дубли; несколько складов/организаций/единиц; период и момент документа; собственные движения; несохранённые строки; права/РЛС; отмена и перепроведение. Последние случаи требуют своего профиля, они не покрыты автоматически текущим лабораторным корпусом.

## Действительно исполнимая проверка

- Начни с `tests/onec_engine/README.md`, `prepare.js` и имеющихся fixtures. Корпус работает на собственной минимальной конфигурации; не называй его проверкой произвольной ERP или AI-генератора.
- Проверь существование и идентичность изолированного стенда, версии движка, источник конфигурации и разрешённые действия. Тестовый модуль очищает свои данные; неизвестная/пользовательская база недопустима.
- Для packaged evidence укажи CLI извлечённого VSIX через документированный `TOOLBOX_CLI`. Исходный bundle и опубликованный пакет — разные источники.
- Разделяй load/update, compilation и execution; проверяй код выхода и лог каждого этапа. Для исполнения нужны свежий result artifact и все ожидаемые outcomes, не один exit code или старый PASS-файл.
- Сравнивай типы, значения, NULL, количество/мультимножество строк; порядок только при заданном контракте. Для исправления допустимые отличия определяются требованием, а не полным равенством старому поведению.
- Нормализация ID, часов и порядка не должна скрывать проверяемую ошибку. Транзакционный rollback не изолирует сеть, файлы и фоновые задания.

## Counterexample и отчёт

Сначала воспроизведи нарушение согласованного правила на допустимых данных. Уменьшая fixture, сохраняй его структурную/ссылочную корректность и то же нарушение; не обещай математически наименьший пример. Лимиты поиска, seed, все попытки и причина остановки входят в evidence. Истечение бюджета без ошибки означает `no_counterexample_found_within_budget`, а не корректность.

Верни source/candidate hashes, профиль/версии, утверждённый oracle, входы и expected/actual, свежие артефакты, ограничения, стоимость/время при наличии. Отдельно обозначь `passed`, `failed`, `not_run`, `unsupported`, `cancelled`; неожиданные результаты не исправляй изменением ожиданий без domain review.
