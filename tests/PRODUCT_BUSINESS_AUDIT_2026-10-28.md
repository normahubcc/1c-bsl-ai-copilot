# Senior business/product audit — кандидат 1.0.5

Дата: 2026-10-28. Область: практическая польза расширения для разработчика 1С, реальные VS Code/Cursor, локальные инструменты и подготовка учебного стенда 1С. NormaHub намеренно не проверяется на этом этапе.

## Решение

**Для внутреннего пилота — GO с известными ограничениями. Для публичного релиза с обещанием надёжного Copilot и проверки ИТС — HOLD.**

Кандидат представляет интерес как помощник разработчика, который уже работает с BSL-файлами и XML/EDT-проектом в VS Code/Cursor. Его перспективное ядро — использование контекста проекта при решении конкретной задачи и получение результата, который удобно проверить и применить в редакторе. Однако качество AI-результата, его стоимость и реальная экономия времени здесь не доказаны: по условиям задачи шлюз не подключался.

Локальные сценарии технически работают, но имеют разную продуктовую ценность. Без AI это набор справочников, каркасов и ограниченных эвристик. Сам по себе такой набор пока не подтверждает преимущество, ради которого разработчик будет регулярно возвращаться и платить. Это продуктовый вывод по наблюдаемым возможностям, а не результат исследования готовности клиентов платить.

Новая проверка в настоящих IDE обнаружила невыполнение обещания инвалидации preview после закрытия вкладки. Практический корпус выявил ложные рекомендации и пропуски локального аудита. Предыдущий положительный локальный отчёт не отменён, но его границы существенно уточнены.

## Важные находки

### P1 — обещание защиты preview после закрытия вкладки не выполняется

Воспроизведение: открыть Module.bsl → создать preview → сохранить исходный файл → закрыть его вкладку → открыть тот же файл → применить старый preview. Код вставляется.

`close-reopen-evidence.json` фиксирует закрытие вкладки через `window.tabGroups.onDidChangeTabs`, отсутствие вкладки в списке и последующее открытие. При этом `workspace.onDidCloseTextDocument` для файла не происходит: редактор оставляет модель в памяти. Проверки `document.isClosed`, объекта документа и версии сохраняют валидность, хотя вкладка закрывалась.

Это не доказательство потери данных: вставка потребовала явного нажатия и undo работает. Но заявленный контракт «после закрытия и повторного открытия необходимо пересоздать preview» неверен. До релиза нужен учёт закрытия последней вкладки исходного файла либо явное изменение контракта, текста UI и тестов. Нынешняя симуляция закрытого TextDocument не заменяет этот реальный сценарий.

### P1 — локальный аудит создаёт ложную уверенность и лишнюю работу

Через toolbox-cli из извлечённого VSIX выполнен отдельный корпус. В 10 целевых проверках правил обнаружены четыре расхождения с ожидаемым смыслом; это специально подобранные пограничные примеры, **не оценка средней точности в процентах**.

| Пример | Фактическое поведение | Последствие |
|---|---|---|
| `Обработчик.Выполнить(Стр)` в цикле | Объявляется выполнением запроса без установления типа объекта | Лишняя диагностика для произвольного метода с тем же именем. |
| Обычный `Попытка; Результат = Запрос.Выполнить(); Исключение; ...` | Рекомендуется метод БСП для отсутствующего свойства структуры | Неприменимая рекомендация вместо анализа реальной конструкции. |
| Напечатанная строка с текстом `Запрос.Текст = Запрос.Текст + ...` | Предупреждение ITS-SEC-001 | Текст программы принимается за выполняемый запрос. |
| Первое присваивание текста запроса с конкатенацией пользовательского ввода | ITS-SEC-001 не выдаётся | Аналогичный заявленному риск пропускается. |

Отдельно `1c_inspect_query` возвращает `{isValid: true, issues: []}` как для постороннего текста, так и для `ВЫБРАТЬ ИЗ`. Для LEFT JOIN без числовой проекции выдаётся совет про ЕСТЬNULL числовых полей. Отсутствие замечаний здесь означает только отсутствие совпадений по нескольким эвристикам, а не валидность запроса.

До продвижения проверки ИТС в основной продукт: исправить эти случаи, разделить синтаксическую проверку и hints, убрать неоднозначное isValid из контракта либо дополнить явным `syntaxChecked: false`, добавить управление правилами и подавление неприменимых рекомендаций. Автоматически менять код по таким рекомендациям нельзя. Code Action сейчас лишь показывает пояснение, а не исправляет код — это правильно с точки зрения текущей ограниченности.

### P1 — полезность шаблона дефицита зависит от неподтверждённых условий

Шаблон требует одинаковых имён измерений в табличной части и регистре. Склад в шапке документа нельзя сопоставить с измерением регистра через текущую форму. Выборка читает `Документ.Заказ.Товары` по Ссылка, а не переданную текущую таблицу строк; работу с несохранёнными изменениями и порядок записи при проведении нужно проверять отдельно.

Имена не сопоставляются со схемой проекта перед генерацией. ПериодКонтроля задаётся вызывающим кодом; блокировки, движения, перепроведение и собственные движения документа не реализованы. Это честно оговорённый каркас, но он не должен становиться главным обещанием «готового проведения». Предпочтительный следующий шаг — явное сопоставление полей/источников по метаданным и небольшой проверенный набор конфигураций.

### P2 — Vanessa local даёт файл, но почти не выполняет задачу пользователя

На двух различных требованиях получены сохранённые тексты требования, название сценария и TODO. **В обоих результатах ноль исполняемых шагов.** Файл нельзя считать реализованным приёмочным тестом или подтверждением бизнес-поведения. Локальный каркас полезен как простой шаблон нового файла, но его отдельная главная карточка переоценивает ценность. AI-режим не оценивался.

### P2 — интерфейс местами дороже результата

Реальная ширина боковой панели в проверке — около 298 px. Длинная форма дефицита требует прокрутки до кнопки и результата; некоторые поля имеют системное оформление, а названия верхних разделов неудачно переносятся. На экранах шаблонов остаются дублирующие представления результата в форме и Action Pilot. Это не функциональная поломка, но повышает стоимость простого действия.

Расширение активируется и по `onStartupFinished`; полезность присутствия его статуса в проектах без BSL не доказана. Приоритет — контекст редактора, одна понятная зона результата, компактные native-команды для простых операций, дополнительный каталог для редких инструментов. Полный новый редизайн сейчас не является главным ограничителем пользы.

## Решение по функциям

| Функция | Практическая ценность и ограничение | Решение |
|---|---|---|
| Inline autocomplete | Частая задача, нативное место в редакторе. Offline-поведение проверено; польза реального ответа и задержка ещё неизвестны. | Оставить как основное направление; не повышать live-verdict. |
| AI-запрос по описанию | Перспективная разница с обычным чатом — контекст проекта и применение в редакторе. Синтаксис/данные/результат AI ещё не проверены. | Оставить один workflow; main prompt и Command Palette — удобные входы, их не надо удалять как «дубли функций». |
| AI-объяснение | Помогает понять чужой код в контексте. Реальное качество здесь не проверено. | Объединить с анализом выделения. |
| Локальная подготовка пакета | Получается применимый черновик для ограниченного SELECT. Эквивалентность в 1С и ускорение на данных не доказаны. | Оставить дополнительным действием после анализа запроса; не называть гарантированной оптимизацией. |
| Шаблон дефицита | Снижает набор повторяющегося текста при точном совпадении схемы. Не готовое проведение. | Доработать сопоставление полей; до этого оставить в дополнительных шаблонах. |
| Перехваты расширения | Узко полезный старт, явный preview; реальная сигнатура поставщика и компиляция не подтверждены. Не создаёт .cfe. | Оставить в общей группе шаблонов. |
| Кнопка формы | Создаёт заготовку команды, но действие и реальная панель остаются TODO/ручной настройкой. | Объединить с шаблонами расширения, не продвигать как самостоятельное готовое решение. |
| Аудит ИТС | Встроенные diagnostics работают, но найденные ложные советы снижают доверие. Нет доказательства полноты ИТС. | Ограничить позиционирование; исправить P1, дать выключение правил, рассмотреть интеграцию с BSL LS. |
| БСП | Фактически 40 статических записей, поиск и примеры. Наличие и версия методов в проекте не проверяются. | Оставить как справочник; не представлять примеры как проектно подтверждённую замену. |
| Vanessa local | Сохраняет требование, но не создаёт исполняемый тест. | Скрыть из главного каталога; переместить в простой шаблон .feature. |
| Vanessa AI | Возможная помощь в создании черновика, зависит от реальной библиотеки шагов. | Оставить в advanced/beta до реального прогона; не заявлять готовый автотест. |
| Технологический журнал | Локально помогает быстро прочитать фрагмент и выделить длительность/блокировку. Причины и советы в значительной степени типовые. | Оставить как предварительный разбор; показывать исходное событие и отделять факт от гипотезы. |
| Метаданные | Полезная инфраструктура контекста; не замена репозиторию метаданных 1С. Поддержана ограниченная группа видов, типы XML в контексте не раскрыты полноценно. | Оставить фоновым контекстом с источником/свежестью; отдельный экран — диагностика доступности. |
| MCP/Sidecar | Позволяют переиспользовать ядро из других клиентов. Не добавляют качества самим эвристикам. | Оставить в дополнительных интеграциях. |
| EPF/TurboConf | Ручная/экспериментальная интеграция. На целевой платформе не подтверждена. | Исключить из основного release promise; держать отдельно как экспериментальные адаптеры. |
| Модели, ключ, billing | Раздельные настройки полезны и проверены в IDE. Управление балансом внешнее; live-доступность моделей/тарифы не проверялись. | Оставить компактное подключение и внешний кабинет; не превращать расширение в billing dashboard. |

## Рынок и отличие от имеющихся инструментов

EDT уже предлагает проверку конфигурации, работу с метаданными, контекстные подсказки, навигацию и средства отладки. BSL Language Server документирует развитую диагностику и подавление отдельных правил. Поэтому конкурировать количеством справочников, небольшим набором эвристик или ещё одним шаблоном процедур невыгодно. Перспективное отличие кандидата — контекстная помощь с проверяемым результатом непосредственно в привычном редакторе. Это вывод из сравнения возможностей, а не доказанная доля рынка. [EDT](https://v8.1c.ru/platforma/1c-enterprise-development-tools/), [BSL LS](https://1c-syntax.github.io/bsl-language-server/diagnostics/).

Для расширения важна экономия внимания: официальные UX-рекомендации VS Code предостерегают от повторения встроенных возможностей и избыточного Webview. Это поддерживает приоритет компактных редакторских действий над ростом числа экранов. [Webviews](https://code.visualstudio.com/api/ux-guidelines/webviews), [Sidebars](https://code.visualstudio.com/api/ux-guidelines/sidebars).

Первичная аудитория пилота: разработчик 1С с BSL и выгрузкой конфигурации в Git, готовый проверять черновики. Пользователь, работающий только в Конфигураторе с .dt/.cf, сначала должен получить поддерживаемую выгрузку и наладить перенос результата. Само расширение этот разрыв пока не закрывает.

## Бизнес-проверка до коммерческого решения

Экономия времени, retention и готовность платить не измерены. Число функций и успешные тесты не заменяют эти показатели. Текущие completion-метрики фиксируют lifecycle/ошибки/нормализацию; поле accepted не наблюдается, поэтому нельзя принимать количество возвращённых ответов за количество полезных принятых дополнений.

Рекомендованный пилот: 5–8 разработчиков, реальные разрешённые задачи из их конфигураций, фиксированная исходная процедура решения и проверка результата в 1С. Оценивать:

1. Время до **проверенного результата**, включая чтение и исправление ответа, против привычного инструмента.
2. Долю задач, дошедших до полезного применения, и причины отказа.
3. Для inline — принятие, последующий undo/переписывание и задержку на реальном шлюзе; для preview — успешное применение после проверки.
4. Повторное использование по задачам в течение недели, а не число открытий панели.
5. Стоимость шлюза на полезный результат после live-этапа, без предположений о текущих тарифах.

До такого пилота обещание окупаемости не обосновано. Предлагаемый продуктовый критерий роста — число подтверждённо полезных применений на активного разработчика в неделю при снижении полного времени решения. Это план измерения, не уже полученная метрика.

## Стенд 1С и остаточные ограничения

Официальная бесплатная учебная 1С **8.3.27.1508 Linux x86_64 скачана**: 1 516 214 922 байта, SHA-256 `71400098eff51a39736fe8ec6077c9818cfbb682548346ccb1d58364e3b9b403`. Одноразовая ссылка с токеном не сохранялась в репозиторий.

Установщик требует root; попытка `sudo -n` остановилась на отсутствии пароля. Пользователю передана команда установки без веб-сервера, ярлыков и автоматической установки зависимостей. Пароль в чат не запрашивается. **Установленная платформа, учебная база, компиляция BSL и исполнение запросов пока не подтверждены.**

Подготовлены [протокол учебного стенда](/home/user/1c-copilot-product-audit-2026-10-28-tl_9ivyl/ONEC_LAB.md) и скрипт обнаружения платформы/создания отдельной пустой базы `onec-lab.py`. Определены сценарии достаточного остатка, дефицита, дубликатов строк, NULL, нескольких складов, склада в шапке, несохранённых изменений, перепроведения, сигнатуры перехвата и кнопки формы. Тестовый JSON проекта не выдаётся за настоящую загруженную конфигурацию.

Учебная версия подходит для небольшой файловой базы и проверки синтаксиса/поведения.
