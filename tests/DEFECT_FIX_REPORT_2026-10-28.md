## Исправления

| Область | Проблема | Полученное поведение |
|---|---|---|
| Предпросмотр | TextDocument остаётся живым после закрытия вкладки, поэтому старый код допускался к вставке после переоткрытия | Учитывается закрытие последней текстовой/diff-вкладки исходного URI. Ревизия захватывается до асинхронной генерации и проверяется после ожиданий при применении. Закрытие одного split не инвалидирует другой открытый split. |
| Запрос в цикле | Произвольный `Обработчик.Выполнить()` объявлялся запросом; проверка зависела от всей строки | Проверка идёт по порядку лексических токенов и учитывает известный конструктор/получателя запроса и переприсваивание. Однострочный цикл не распространяет предупреждение на вызов после `КонецЦикла`. |
| Склейка запроса | Пропускалась первая динамическая установка текста, а напечатанный код считался исполняемым | Анализируется присваивание `.Текст` известному запросу; строки и комментарии не рассматриваются как исполняемый BSL. |
| БСП | Любой dotted expression в `Попытка` выдавался за отсутствие свойства; читатель предлагался для записи | Неподтверждённые эвристики убраны. Совет о чтении реквизита не предлагается для очевидной записи. Каталог БСП сохранён. |
| Inspection | `isValid: true` возвращалось для постороннего/сломанного текста; любой LEFT JOIN вызывал совет о числах | Добавлены структурные отказы. `syntaxChecked: false`; `isValid: null` означает отсутствие подтверждённой валидности. NULL-подсказка связана с арифметикой по присоединённому полю внутри конкретного запроса пакета. Константные строки не создают ложные подсказки. |
| Аудит | Неприменимое правило нельзя было отключить | Добавлены `auditDisabledRules`, переход из панели в настройки и комментарии disable-next-line/disable/enable для конкретных правил. Настройка обновляет существующие diagnostics. Пустой файл не получает лишнюю editor diagnostic. |
| Дефицит | Поля обязаны были иметь одинаковые имена; склад из шапки и текущие несохранённые строки не поддерживались | Явные сопоставления полей и ресурса, `@РеквизитШапки`, выбор текущих строк или сохранённого источника. При доступной схеме проверяются объект, табличная часть, поля, известные роли и полнота измерений. Отсутствующая информация не заменяется демо-данными. |
| Vanessa | Требование без шагов выглядело результатом генерации теста | Добавлен ввод настоящих шагов пользователя и таблиц, корректное экранирование и проверка формы таблиц. Показываются число шагов и отсутствие подтверждённого исполнения. Для требования без шагов явно сообщается, что исполняемых шагов нет. |
| Перехваты | Не поддерживались значения параметров по умолчанию и запятые внутри строк | Параметры разбираются с учётом строк, сохраняют константные defaults; в `ПродолжитьВызов` передаются только имена. Проверяются вид известного события, директивы, дубли и недопустимые идентификаторы. |
| Кнопка формы | Предполагалось фиксированное имя командной панели | Пользователь задаёт имя панели; код ищет её и явно сообщает об отсутствии. Действие команды остаётся явно обозначенной бизнес-логикой шаблона. |
| AI-запрос | Ответ только из комментариев мог выглядеть готовым кодом | Возвращается понятное предложение уточнить схему/задачу, без выдачи комментариев за реализованный запрос. |

Новые возможности общего ядра доступны в IDE, MCP и Sidecar. MCP schemas описывают новые параметры; Sidecar передаёт сопоставления/источник/явные шаги в то же ядро. В этой итерации облачные запросы не выполнялись и токены публикации не сохранялись.

## Остаточные границы и решение

Ранее воспроизведённые дефекты предпросмотра и перечисленные ложные заключения проверок исправлены. Шаблон дефицита получил недостающие возможности и положительное исполнение в движке. Это существенно сильнее предыдущего offline-аудита.

**Утверждать готовность всего продукта на 100% по-прежнему нельзя.** Локальные проверки не являются полным парсером или сертификатом ИТС. Контроль дефицита не реализует транзакцию проведения, блокировки, запись движений и отказ за конфигурацию. Реальное исполнение перехватов .cfe, GUI формы и конкретной библиотеки Vanessa этой проверкой не подтверждено. Положительное принятие облачного inline в IDE, live p95/p99, качество/стоимость AI на задачах пользователей и конкурентное проведение на production СУБД остаются отдельными проверками. Три прежних успешных gateway smoke-вызова не заменяют их.

Кандидат подходит для ограниченного пилота с указанным объёмом проверенных функций; массовый релиз с более широкими обещаниями требует оставшихся интеграционных и live-проверок. Сборка, коммит, публикация и live-подтверждение остаются разными состояниями.

Инструкция по GitHub, Open VSX, Инфостарту, MCP Registry, Glama и Product Hunt: `docs/PUBLISHING.md`. Никакие публикации не выполнялись.
