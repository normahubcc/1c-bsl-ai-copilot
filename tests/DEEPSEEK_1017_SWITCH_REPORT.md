## Реальные запросы NormaHub

Каталог `/v1/models` вернул HTTP 200, 34 модели и оба DeepSeek ID. После этого сделаны три небольших тестовых вызова через реальные `NormaHubClient`/`runTask` текущего исходника. Подмена сетевых ответов не использовалась; вне Extension Host предоставлена только редакторская конфигурация/неиспользуемый импорт vscode. Передавался исключительно тестовый код.

| Задача | Request model | HTTP | Время клиента | Проверенный результат |
|---|---|---|---|---|
| Дополнение строки `Сообщить(` | deepseek-v4.1-flash-1017 | 200 | 5,03 с | Ответ `"Проверка 1017");` принят настоящим normalizer. |
| Функция получения дефицита по тестовой схеме | deepseek-v4.1-flash-1017 | 200 | 24,80 с | Получен BSL с группировкой по Номенклатуре/Складу, параметрами и ЕСТЬNULL. Исполнение в 1С не проверено. |
| Объяснение обычного `Попытка/Исключение` вокруг запроса | deepseek-v4.1-flash-1017 | 200 | 24,90 с | Модель корректно отметила отсутствие доказательства обращения к свойству структуры. Ответ остаётся аналитическим черновиком. |

Важная граница: **все запросы отправлены с model=deepseek-v4.1-flash-1017, но поле model в ответах шлюза — deepseek-v4.1-flash**. Подтверждено принятие ID 1017 шлюзом; точная ревизия upstream по этому ответу независимо не подтверждается. Расширение не заменяет запрошенный ID обратно на legacy.

Три вызова — smoke, не статистика p95/p99 и не доказательство качества на реальных конфигурациях. Около 25 секунд для reasoning-задач и 5 секунд для маленького дополнения не дают основания обещать быстрый ghost text. Запрос дефицита читает виртуальные остатки без отбора по выбранным товарам: потенциальную стоимость нужно оценить на данных, а не объявлять результат оптимизированным по шаблону.

Ключ не включён в исходники, отчёт или логи. Временный файл с правами 0600 удалён после вызовов. В логах сохранены model/status/время/usage и тестовые ответы, без заголовков авторизации. Денежная стоимость из поля usage.credit не интерпретируется без подтверждённой единицы тарификации.
