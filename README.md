# 1C BSL AI Copilot (NormaHub)

Инструмент помощи в разработке для встроенного языка **1С:Предприятие 8.3 (BSL)** в редакторах **Cursor**, **VS Code**, **Windsurf** и **VSCodium**.

* **VS Code Marketplace**: [marketplace.visualstudio.com/items?itemName=Normahub.1c-bsl-ai-copilot](https://marketplace.visualstudio.com/items?itemName=Normahub.1c-bsl-ai-copilot)
* **Open VSX Registry**: [open-vsx.org/extension/normahub/1c-bsl-ai-copilot](https://open-vsx.org/extension/normahub/1c-bsl-ai-copilot)
* **Репозиторий GitHub**: [github.com/normahubcc/1c-bsl-ai-copilot](https://github.com/normahubcc/1c-bsl-ai-copilot)

Работает через шлюз [NormaHub](https://normahub.cc) без необходимости настройки VPN и прокси. Тарификация строится по модели Pay-As-You-Go за фактически переданные и сгенерированные токены, без обязательных ежемесячных подписок.

## Ключевые возможности

### 1. Автодополнение кода BSL в процессе набора (Ghost Text)
* Построчное и блочное дополнение процедур, функций, управляющих конструкций и циклов прямо в редакторе (подробности о задержках — в разделе «Автодополнение BSL: как это работает»; фиксированных гарантий отклика в миллисекундах нет).
* Автоматическая расстановка директив компиляции: `&НаКлиенте`, `&НаСервере`, `&НаСервереБезКонтекста`.
* Подстановка конструкций Библиотеки Стандартных Подсистем (БСП) без лишних обращений к базе данных.
* Корректная обработка структуры `Если ... Тогда ... ИначеЕсли ... КонецЕсли;` и циклов `Для Каждого ... Из ... Цикл`.

### 2. Поддержка выбора моделей под задачу
Плагин не привязан к одной фиксированной нейросети. В панели «Баланс» или через `settings.json` можно переключать рабочую модель в зависимости от сложности задачи:

| Модель | Рекомендуемое применение | Характеристики |
|---|---|---|
| `deepseek-v4.1-flash` | **Основная рабочая модель** | Flash-класс скорости, знание русскоязычного синтаксиса BSL (~0.04 ₽ за 1k токенов); live p95 задержки не замерен, см. тесты |
| `gpt-6.1-sol` | Комплексные алгоритмы | Сложная логика проведения, расчётные механизмы, закрытие месяца |
| `gpt-6-sol` | Точный анализ | Рассуждения по многоуровневым выборкам и сложным структурам |

### 3. Контекстный анализ открытых вкладок (Multi-Tab Context)
* Анализ соседних открытых файлов (`.bsl`, `.os`) в рабочей области.
* Извлечение сигнатур экспортируемых процедур и функций (`Экспорт`) из смежных модулей.
* Передача интерфейсов общих модулей в промпт для исключения ошибок в именах методов и числе параметров.

### 4. Конструктор пакетов запросов 1С по стандартам ИТС (`Ctrl+Alt+Q`)
* Формирование пакетов запросов по текстовому описанию задачи на русском языке.
* Соблюдение правил производительности:
  * Выделение исходных данных во временные таблицы (`ПОМЕСТИТЬ ВТ_...`) с явной индексацией (`ИНДЕКСИРОВАТЬ ПО`).
  * Параметризация виртуальных таблиц в круглых скобках без прямых левых соединений.
  * Использование `МенеджерВременныхТаблиц`.
  * Защита числовых полей от `NULL` через `ЕСТЬNULL(..., 0)`.
  * Очистка временных таблиц в конце пакета (`УНИЧТОЖИТЬ ВТ_...`).

### 5. Генератор перехватов для расширений (`cfe`) (`Ctrl+Alt+E`)
* Разработка доработок типовых конфигураций (ERP, КА, УТ, ЗУП, БП) без снятия с поддержки:
  * **`&Вместо`**: шаблон вызова с сохранением типового поведения через `ПродолжитьВызов(...)`.
  * **`&Перед`**: валидация входных реквизитов и управление флагом `Отказ`.
  * **`&После`**: постобработка движений и заполнение дополнительных регистров.
  * **`&ИзменениеИКонтроль`**: аккуратные вставки с тегами `#Вставка` и `#КонецВставки`.
  * Программное добавление кнопок и команд в процедуре `ПриСозданииНаСервере`.

### 6. Справочник и генератор методов БСП 3.1 (`Ctrl+Alt+B`)
* Быстрая вставка типовых методов для исключения избыточного чтения базы данных:
  * `ОбщегоНазначения.ЗначениеРеквизитаОбъекта(...)` вместо ресурсоёмкого `ПолучитьОбъект()`.
  * `СтроковыеФункцииКлиентСервер.РазложитьСтрокуВМассивПодстрок(...)`.
  * `ДлительныеОперации.ЗапуститьВыполнениеВФоне(...)` для неблокирующих фоновых заданий.
  * `Пользователи.АвторизованныйПользователь()`.

### 7. Аудит стандартов разработки ИТС (`Ctrl+Alt+I`)
* Проверка модуля или выделенного фрагмента на распространённые ошибки:
  * **`ITS-PERF-001`**: вызов запроса внутри тела цикла (`Для Каждого`).
  * **`ITS-PERF-002`**: обращение к виртуальной таблице без условий в параметрах среза.
  * **`ITS-LOCK-001`**: отсутствие явной блокировки данных в обработке проведения.
  * **`ITS-UI-003`**: устаревшие синхронные модальные вызовы.
  * **`ITS-MUTABLE-001`**: передача мутабельных значений (`ТаблицаЗначений`) между клиентом и сервером.
  * **`ITS-BSP-001`**: замена ручных выборок на готовые методы БСП.

### 8. Сценарии тестирования Vanessa Automation (`Ctrl+Alt+V`)
* Генерация сценариев на языке Gherkin (`.feature`) по логике документа или ТЗ:
  * Проверка заполнения реквизитов и табличных частей.
  * Контроль отказов при нехватке остатков на складах.
  * Проверка движений регистров накопления и сведений.

### 9. Анализ инцидентов Технологического Журнала (`Ctrl+Alt+T`)
* Парсинг строк ТЖ с событиями `TLOCK`, `TDEADLOCK`, `EXCP`, `SDBL`.
* Локализация области блокировки (имя регистра, исключительный/разделяемый режим, длительность ожидания) и рекомендации по оптимизации транзакций.

## Автодополнение BSL: как это работает, ограничения и диагностика

### Как работает
1. `BSLInlineCompletionProvider` зарегистрирован для `file:bsl`, `file:1c`, `file:oscript` и `untitled:bsl` (несохранённые `1c`/`oscript` пока не покрыты).
2. Каждый вызов получает identity (URI + версия документа + позиция + монотонный id); предыдущий запрос отменяется.
3. Trailing debounce `normahub1c.debounceMs` (по умолчанию 250 мс): серия нажатий схлопывается в один запрос к последней позиции.
4. Контекст: 50 строк до и 15 после курсора, AST-scope (метод, `Перем`, циклы, `Попытка`, директива), реальные метаданные конфигурации, сигнатуры соседних вкладок, методы БСП — всё в жёстких лимитах (`contextBudgetChars`, по умолчанию 12000).
5. Запрос уходит только в быструю модель `autocompleteModel` (по умолчанию `deepseek-v4.1-flash`); тяжёлые reasoning-модели (`reasoningModel`, по умолчанию `gpt-6.1-sol`) используются только генератором запросов и объяснениями, никогда ghost text.
6. Ответ модели проходит консервативную нормализацию: только чистый BSL становится ghost text, сомнительное отбрасывается.

### Когда запрос НЕ отправляется
* Выключено `enableInlineCompletion` или нет API-ключа (тот же ключ, что у панели: SecretStorage → `NORMAHUB_API_KEY`).
* Пустая первая строка; токен отмены уже отозван; документ изменился во время debounce.
* Синтетическая демо-схема метаданных в промпт не попадает (только реальная конфигурация).

### Отмена (cancellation)
* Продолжение печати, смена позиции/документа или отзыв токена VS Code отменяют предыдущий запрос: debounce-таймер чистится, HTTPS-запрос уничтожается (`req.destroy()`), устаревший ответ отбрасывается даже если сервер ответил позже.
* Отмена тихая: никаких тостов и шума в логах. Оплаченных устаревших запросов при burst-вводе нет (10 нажатий → 1 сетевой вызов, проверено тестами).

### Что влияет на задержку
Debounce + построение контекста (тёплый кэш метаданных ≈ 0 мс) + сеть шлюза + размер ответа. Замерено только на fake-транспорте (медиана end-to-end ~2–3 мс при задержке сети 2 мс, p95 скошен искусственной задержкой 200 мс в сценарии отмены). Live p50/p95/p99 с реальным ключом не замерены — числовых гарантий отклика нет.

### Что отправляется / не отправляется
* Отправляется: фрагмент кода вокруг курсора, имена объектов реальной конфигурации, сигнатуры открытых модулей, системный промпт стандартов.
* Все облачные AI-запросы расширения отправляются только на фиксированный шлюз `https://api.normahub.cc/v1`. Пользовательский endpoint не настраивается.
* Диагностика (`normahub1c.completionDebug`, выключена по умолчанию) пишет только числа и классы ошибок (`cancelled/timeout/unauthorized/rate-limited/gateway/parse/context/unknown`) — без кода, промптов и ключей.

### Настройки
| Параметр | По умолчанию | Смысл |
|---|---|---|
| `normahub1c.enableInlineCompletion` | `true` | Ghost text вкл/выкл |
| `normahub1c.debounceMs` | `250` | Trailing debounce, мс |
| `normahub1c.requestTimeoutMs` | `25000` | Таймаут HTTPS (лимит шлюза); запрос уничтожается |
| `normahub1c.maxCompletionLines` / `maxCompletionChars` | `20` / `1000` | Лимиты ответа (превышение → отброс, не обрезка) |
| `normahub1c.contextBudgetChars` | `12000` | Лимит контекста; приоритет — метод и хвост курсора |
| `normahub1c.completionDebug` | `false` | Санитизированный лог фаз в OutputChannel |

## Установка и начало работы

### Вариант 1. Установка из каталога расширений
Найдите **1C BSL AI Copilot** в поиске вкладки Extensions (`Ctrl+Shift+X`) в VS Code, Cursor или Windsurf и нажмите **Install**.

### Вариант 2. Установка через VSIX-пакет
```bash
# Для VS Code
code --install-extension 1c-bsl-ai-copilot-1.0.3.vsix

# Для Cursor
cursor --install-extension 1c-bsl-ai-copilot-1.0.3.vsix
```

### Первоначальная настройка
1. Зарегистрируйтесь на платформе [NormaHub](https://normahub.cc) и выпустите API-ключ в личном кабинете.
   * *Примечание:* при создании аккаунта доступен промокод `1CPROMO` (начисляет стартовые $0.10 на баланс для тестирования возможностей расширения).
2. Откройте панель **1С Copilot** на боковой панели редактора, перейдите во вкладку **Баланс** и сохраните ключ в поле ввода.
3. Ключ безопасно сохраняется в системном хранилище VS Code SecretStorage.

## Использование с внешними AI-агентами (1C MCP Server)

В состав пакета входит сервер **Model Context Protocol (MCP)**, позволяющий подключать к инструментам 1С внешних агентов (Cursor Composer, Claude Code, Windsurf, Cline).

### Конфигурация подключения (`mcp.json`):
```json
{
  "mcpServers": {
    "1c-copilot": {
      "command": "node",
      "args": ["<путь_к_плагину>/bin/mcp-server-1c.js"],
      "env": {
        "NORMAHUB_API_KEY": "nr_hub_..."
      }
    }
  }
}
```

Доступные инструменты MCP:
* `1c_scan_metadata`: получение дерева объектов конфигурации (справочники, документы, регистры).
* `1c_audit_standards`: статический аудит BSL-кода на правила ИТС и БСП.
* `1c_build_batch_query`: построение пакета запросов с временными таблицами.
* `1c_inspect_query`: проверка текста запроса на антипаттерны СУБД.
* `1c_generate_extension`: создание перехвата метода для расширения.
* `1c_bsp_search`: поиск по типовым процедурам БСП.
* `1c_generate_bdd_feature`: генерация BDD-сценариев Vanessa Automation.
* `1c_analyze_tech_log`: разбор событий Технологического Журнала.

## Фоновый ассистент для 1С:Конфигуратора (Sidecar)

Для работы в стандартном **1С:Конфигураторе 8.3** доступен локальный фоновый демон.

### Запуск Sidecar:
```bash
python3 sidecar/main.py daemon --with-clipboard
```

### Функции:
* **Интеграция через буфер обмена**: скопируйте в Конфигураторе комментарий вида `// перехват ОбработкаПроведения`, `// запрос остатки` или фрагмент лога `// тж` — Sidecar преобразует содержимое буфера в готовый код или диагностический отчёт.
* **Локальный REST API (`http://127.0.0.1:18833`)**: эндпоинты `/v1/audit`, `/v1/query`, `/v1/extension`, `/v1/bdd`, `/v1/techlog`, `/v1/complete` для вызова из OneScript (`oscript`), внешних обработок (`.epf`) или сборочных пайплайнов.
