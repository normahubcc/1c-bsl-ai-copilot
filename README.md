# 1C BSL AI Copilot (NormaHub)

**Открытая бета 1.0.12.** Инструмент помощи в разработке для встроенного языка **1С:Предприятие 8.3 (BSL)** в **VS Code** и **Cursor**. Работа в Windsurf и VSCodium пока не подтверждена тем же набором проверок.

AI генерирует **черновики**, которые разработчик просматривает и проверяет в своей 1С перед использованием. При облачных запросах фрагмент BSL, ограниченный контекст метаданных и задача отправляются в NormaHub; локальные проверки, шаблоны и MCP работают без API-ключа. Скорость и корректность AI-ответа не гарантируются. Для сообщений об ошибках используйте [GitHub Issues](https://github.com/normahubcc/1c-bsl-ai-copilot/issues) на обезличенных примерах: не публикуйте ключи, код клиента или персональные данные.

* **VS Code Marketplace**: [marketplace.visualstudio.com/items?itemName=Normahub.1c-bsl-ai-copilot](https://marketplace.visualstudio.com/items?itemName=Normahub.1c-bsl-ai-copilot)
* **Open VSX Registry**: [open-vsx.org/extension/normahub/1c-bsl-ai-copilot](https://open-vsx.org/extension/normahub/1c-bsl-ai-copilot)
* **Репозиторий GitHub**: [github.com/normahubcc/1c-bsl-ai-copilot](https://github.com/normahubcc/1c-bsl-ai-copilot)

Работает через шлюз [NormaHub](https://normahub.cc) без необходимости настройки VPN и прокси. Тарификация строится по модели Pay-As-You-Go за фактически переданные и сгенерированные токены, без обязательных ежемесячных подписок.

## Язык интерфейса

Выберите **RU / EN** справа сверху в панели 1C Copilot. Переключение не очищает запрос, введённые параметры и предпросмотр. Выбор сохраняется для следующих открытий расширения; без сохранённого выбора используется язык IDE. BSL-код, имена метаданных, API БСП и текст пользователя не переводятся. Названия команд и описания настроек VS Code локализуются по языку самой IDE.

Choose **RU / EN** in the top-right corner of the 1C Copilot panel. Switching preserves your inputs and code previews. The choice is remembered across sessions; the IDE language is used initially. BSL code, metadata identifiers, BSP APIs and user content stay unchanged. VS Code command titles and settings descriptions follow the IDE language.

## Рабочие сценарии

- **BSL-автодополнение:** ghost text в VS Code/Cursor, отмена устаревших запросов, ограниченный контекст и нормализация ответа. Настройка `autocompleteModel` независима от генерации.
- **Запрос по описанию:** AI-черновик с реальными метаданными и кодом редактора. Один workflow из панели, Command Palette и горячих клавиш. Preview → открыть отдельно, скопировать или применить к исходному BSL-файлу.
- **Проверить и объяснить BSL:** локальные эвристики по запросам в циклах, модальным вызовам, явным блокировкам и части query-антипаттернов; AI-объяснение выделенного фрагмента. Проверки не заменяют синтаксический контроль, BSL Language Server и запуск в 1С.
- **Шаблон контроля дефицита:** один регистр накопления, виртуальная таблица `Остатки`, явно указанные измерения и один числовой ресурс. Все измерения должны существовать в табличной части и регистре. Результат — запрос, требующий подключения к транзакциям/движениям/отказу документа.
- **Преобразование запроса:** один SELECT с одним виртуальным JOIN переносится в пакет с сохранением имён полей и NULL-семантики. Вложенные выборки, пакеты, строковые литералы и `*` оставляются без изменений с пояснением. Результат открывается отдельно: исходная выборка становится вторым результатом `ВыполнитьПакет()` (индекс 1), вызывающий код нужно адаптировать. Ускорение определяется замерами и планом запроса.
- **Шаблоны расширений и БСП:** BSL-перехваты `&Вместо`, `&Перед`, `&После`, функции с возвратом результата, каркас кнопки управляемой формы и справочник примеров БСП. Сигнатуру/контекст/доступность метода нужно сверить с конфигурацией. Готовый `.cfe` собирается в Конфигураторе. `&ИзменениеИКонтроль` без исходного метода не генерируется.
- **Vanessa .feature:** локальный каркас сохраняет полное требование и заданные объекты без придуманных пользователей/товаров/сумм. Отдельный AI-режим создаёт черновик по требованию. Шаги проверяются по установленной библиотеке Vanessa, неизвестные данные заполняются вручную.
- **Технологический журнал:** локальная сводка поддерживаемых событий, ожиданий, исключений и SQL от 1 секунды. Нераспознанный ввод явно отмечается. Рекомендации служат направлениями проверки, а не установленной причиной инцидента.
- **Метаданные:** XML/EDT или `metadata.json` в корне текущего проекта; пустая схема остаётся пустой. Кнопка «Сканировать» сбрасывает кэши. В multi-root используется проект активного файла. JSON-импорт валидируется, максимум 8 МБ; в prompt включается ограниченная часть схемы.

Применение кода связано с URI, позицией и версией исходного документа. Смена активного файла не меняет цель. Изменение исходного модуля после генерации блокирует применение устаревшего результата; preview можно открыть отдельно. Один preview применяется один раз. Генерация сама файлы не изменяет.

Облачные задачи используют только `https://api.normahub.cc/v1`. Локальные проверки, шаблоны и MCP не требуют ключа. Модели: `deepseek-v4.1-flash-1017`, `gpt-6.1-sol`, `gpt-6-sol`; доступность и стоимость проверяйте в своём кабинете NormaHub. Сохранённый ID `deepseek-v4.1-flash` автоматически направляется на `deepseek-v4.1-flash-1017` без перезаписи пользовательских настроек. Модель генерации (`reasoningModel`) настраивается отдельно от модели ghost text. Из панели можно отменить AI-задачу. Пустые и обрезанные лимитом токенов ответы не принимаются как готовый результат.

### Импорт metadata.json

Файл содержит `name`, необязательную `version` и массив `objects`. Объект содержит `kind`, `name`, необязательные `fields` и `tabularSections`; поле содержит `name` и необязательный `type`. Поддерживаются `Документ`, `Справочник`, `РегистрНакопления`, `РегистрСведений`, `ПланВидовХарактеристик`, `Перечисление`. Дубли объектов и некорректные имена отклоняются. Повторное сканирование перечитывает файл; автоматическая инвалидация inline-контекста отслеживает файлы описания конфигурации и JSON.

## Автодополнение BSL: как это работает, ограничения и диагностика

### Как работает
1. `BSLInlineCompletionProvider` зарегистрирован для `file:bsl/1c/oscript` и `untitled:bsl/1c/oscript`.
2. Каждый вызов получает identity (URI + версия документа + позиция + монотонный id); предыдущий запрос отменяется до асинхронного чтения ключа. Ответ для изменённого или закрытого документа отбрасывается; деактивация расширения отменяет запрос.
3. Trailing debounce `normahub1c.debounceMs` (по умолчанию 250 мс): серия нажатий схлопывается в один запрос к последней позиции.
4. Контекст: 50 строк до и 15 после курсора, AST-scope (метод, `Перем`, циклы, `Попытка`, директива), реальные метаданные конфигурации, сигнатуры соседних вкладок, методы БСП — всё в жёстких лимитах (`contextBudgetChars`, по умолчанию 200000).
5. Ghost text использует настройку `autocompleteModel` (по умолчанию `deepseek-v4.1-flash-1017`); модель `reasoningModel` (по умолчанию `gpt-6.1-sol`) используется запросами, AI-черновиками BDD и объяснениями. Селекторы этих настроек независимы.
6. Кэш учитывает изменения metadata.json и сохранённых XML/EDT-файлов; сигнатуры не извлекаются из строк и комментариев. Предпросмотр привязан к конкретному открытому документу и не применяется после его закрытия и повторного открытия.
7. Ответ модели проходит консервативную нормализацию: только чистый BSL становится ghost text, сомнительное отбрасывается.

### Когда запрос НЕ отправляется
* Выключено `enableInlineCompletion` или нет API-ключа (тот же ключ, что у панели: SecretStorage → `NORMAHUB_API_KEY`).
* Пустая первая строка; токен отмены уже отозван; документ изменился во время debounce.
* При отсутствии реальной схемы примерные объекты не создаются; inline-контекст метаданных пуст.

### Отмена (cancellation)
* Продолжение печати, смена позиции/документа или отзыв токена VS Code отменяют предыдущий запрос: debounce-таймер чистится, HTTPS-запрос уничтожается (`req.destroy()`), устаревший ответ отбрасывается даже если сервер ответил позже.
* Отмена тихая: никаких тостов и шума в логах. Тестовый burst до отправки схлопывается из 10 нажатий в один вызов. Отмена уже отправленного запроса не гарантирует отмену обработки или тарификации на стороне шлюза.

### Что влияет на задержку
Debounce + построение контекста + сеть шлюза + размер ответа. В ограниченном live-прогоне 1017 от 2026-10-31 (пять inline-вызовов, одна среда) медиана API была 6,183 с, nearest-rank p95 — 6,758 с. Это не production SLO и не гарантия будущей задержки; целевой порог интерактивного автодополнения пока не подтверждён. Отдельный fake-бенчмарк измеряет только локальный код и искусственную задержку.

### Что отправляется / не отправляется
* Отправляется: фрагмент кода вокруг курсора, имена объектов реальной конфигурации, сигнатуры открытых модулей, системный промпт стандартов.
* Все облачные AI-запросы расширения отправляются только на фиксированный шлюз `https://api.normahub.cc/v1`. Пользовательский endpoint не настраивается.
* Диагностика (`normahub1c.completionDebug`, выключена по умолчанию) пишет только числа, статус завершения и классы ошибок (`cancelled/timeout/unauthorized/rate-limited/gateway/parse/truncated/context/unknown`) — без кода, промптов и ключей.

### Настройки
| Параметр | По умолчанию | Смысл |
|---|---|---|
| `normahub1c.enableInlineCompletion` | `true` | Ghost text вкл/выкл |
| `normahub1c.debounceMs` | `250` | Trailing debounce, мс |
| `normahub1c.requestTimeoutMs` | `25000` | Таймаут HTTPS; запрос уничтожается |
| `normahub1c.maxCompletionLines` / `maxCompletionChars` | `20` / `1000` | Лимиты ответа (превышение → отброс, не обрезка) |
| `normahub1c.contextBudgetChars` | `200000` | Лимит контекста; приоритет — метод и хвост курсора. Большие значения заметно дороже и медленнее |
| `normahub1c.completionDebug` | `false` | Санитизированный лог фаз в OutputChannel |

## Установка и начало работы

### Вариант 1. Установка из каталога расширений
Найдите **1C BSL AI Copilot** в поиске вкладки Extensions (`Ctrl+Shift+X`) в VS Code или Cursor и нажмите **Install**. Проверьте, что версия в каталоге совпадает с номером релиза; публикация в разных каталогах может появиться не одновременно.

### Вариант 2. Установка через VSIX-пакет
```bash
# Для VS Code
code --install-extension /путь/к/скачанному-файлу.vsix

# Для Cursor
cursor --install-extension /путь/к/скачанному-файлу.vsix
```

### Первоначальная настройка
1. Зарегистрируйтесь на платформе [NormaHub](https://normahub.cc) и выпустите API-ключ в личном кабинете.
2. Откройте панель **1С Copilot** на боковой панели редактора, откройте **Подключение** и сохраните ключ в поле ввода.
3. Ключ безопасно сохраняется в системном хранилище VS Code SecretStorage.

## Внешние интеграции (дополнительная настройка)

### MCP

Локальные инструменты работают без NormaHub API key. В `mcp.json` внешнего клиента укажите путь к установленному расширению:

```json
{
  "mcpServers": {
    "1c-copilot": {
      "command": "node",
      "args": ["<путь-к-расширению>/bin/mcp-server-1c.js"]
    }
  }
}
```

Девять инструментов: `1c_scan_metadata`, `1c_audit_standards`, `1c_build_batch_query`, `1c_inspect_query`, `1c_refactor_query`, `1c_generate_extension`, `1c_bsp_search`, `1c_generate_bdd_feature`, `1c_analyze_tech_log`.

`1c_build_batch_query` требует `entityName`, `tabularSection`, `registerName` и `fields` — все измерения, затем один числовой ресурс. `1c_refactor_query` может вернуть неизменённый текст и `reason`; клиент должен учитывать отказ и смену индекса результата пакета. BDD tool возвращает локальный каркас (`draft: true`), без облачной генерации.

### Sidecar

Требуются Python 3 и Node.js. Локальная логика Sidecar и MCP использует одно собранное ядро `dist/toolbox-cli.js`, которое включено в VSIX. Для исходников сначала выполните `npm run build`. При необходимости задайте путь к Node через `NORMAHUB_NODE`.

```bash
python3 sidecar/main.py daemon
# Наблюдение за буфером включается отдельно:
python3 sidecar/main.py daemon --with-clipboard
```

HTTP по умолчанию: `http://127.0.0.1:18833`. `/health` показывает доступность демона, не баланс и не готовность AI. `SIDECAR_AUTH_TOKEN`, если задан, требуется в `Authorization: Bearer …`; для проверки из расширения та же переменная должна быть задана в окружении IDE. При удалённом bind токен обязателен.

REST: `/v1/audit`, `/v1/query`, `/v1/query/refactor`, `/v1/extension`, `/v1/bdd`, `/v1/techlog`, `/v1/complete`. Запросы передаются объектами JSON, ошибочные параметры возвращают 400. `/v1/query` требует `entity`, `tabular`, `register`, `fields`. `/v1/complete` использует `NORMAHUB_API_KEY` из окружения Sidecar, отдельно от VS Code SecretStorage.

В буфере `// запрос {…}` принимает те же явные параметры JSON. Свободное описание не подменяется шаблоном чужой конфигурации. `// перехват ИмяМетода`, `// bdd ИмяДокумента`, `// тж` обрабатываются локально.

[Исходники внешней обработки и ручная сборка](epf/README.md), [экспериментальный адаптер TurboConf](turboconf/README.md). Готовой `.epf` в пакете нет; live-работа этих адаптеров в 1С/TurboConf пока не подтверждена.

## Проверки и шаблоны 1.0.8

- Предпросмотр привязан к версии документа и времени жизни последней вкладки исходного файла. После закрытия и повторного открытия вкладки сформируйте результат заново; копирование и открытие отдельно остаются доступны.
- Локальный аудит использует ограниченные лексические правила. `normahub1c.auditDisabledRules` отключает отдельные правила; комментарии `// normahub-disable-next-line ITS-PERF-001`, `// normahub-disable ITS-UI-003` и `// normahub-enable ITS-UI-003` позволяют подавлять неприменимые замечания.
- `1c_inspect_query` возвращает `syntaxChecked: false`. `isValid: null` означает отсутствие подтверждения синтаксиса, а не корректность запроса; `false` означает найденную структурную ошибку. Производительность и поведение проверяются в 1С на своих данных.
- Контроль дефицита поддерживает сопоставления `Номенклатура=Товар`, `Склад=@СкладОтгрузки`, ресурс `Количество=Вес`. `@` берёт поле шапки. Можно выбрать текущую табличную часть модуля объекта на сервере либо сохранённые строки базы по ссылке. При доступных метаданных проверяются объект, табличная часть, поля и известные роли измерений/ресурсов; неизвестные типы явно отмечаются в комментариях. Это запрос контроля, а не готовая транзакция проведения: период, собственные движения, блокировки и отказ требуют логики конфигурации.
- В Vanessa можно передать реальные шаги из своей библиотеки и таблицы данных. Требование без шагов сохраняется как требование; число шагов и отсутствие подтверждённого исполнения показываются явно. Продукт не выдумывает библиотечные шаги из свободного текста без AI.
- Перехваты сохраняют константные значения параметров по умолчанию, включая строки с запятыми. В `ПродолжитьВызов` передаются только имена параметров.

### Native review и проверка запроса (локальный кандидат 1.0.11)

В preview доступны native diff захваченного исходника и мастер proposed проверки без ручного JSON: полный запрос, независимое требование, типизированные ожидаемые строки/CSV. Профиль runner v2 позволяет явно задать дополнительные строковые, числовые, логические параметры, дату и NULL; `Дата` и `Ссылка` остаются значениями доверенной учебной конфигурации. Профиль v1 принимает только эти два параметра. [Инструкция](docs/EXTENSION_WORKFLOWS.md). Signed receipt подтверждает только выбранный запрос в закреплённом профиле; полный BSL, бизнес-approval и corporate policy им не подтверждаются. Live AI и условия production-поставки проходят отдельную квалификацию.
